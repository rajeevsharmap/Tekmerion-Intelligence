# Autonomous Financial Crime Investigation Agent

> Architecture reference: `docs/ARCHITECTURE.md` (target design) and
> `docs/backend_implementation_status.md` (current status against it).

Built for the **Smart Horizon International Hackathon** (48-hour build).
Repo: https://github.com/rajeevsharmap/Tekmerion-Intelligence

## What the app does

Financial institutions generate millions of fraud signals a day, and today
most of the investigation work is manual. This project automates the
pipeline end-to-end:

1. **Detect** anomalies using deterministic, explainable rules (not a
   black-box model) - 4 typologies: smurfing, reverse smurfing, money mule,
   account swap/takeover.
2. **Bundle** related alerts for the same account into a **case**.
3. **Gather case-specific evidence** around each case - a transaction graph
   for structuring patterns, a timeline for velocity patterns, a
   behavioral transaction-vs-time view for account takeover.
4. **Argue both sides** with two LLM agents (fraud vs. legitimate), resolved
   by a third Contradiction Agent.
5. **Evaluate** the whole pipeline against a mock dataset with known ground
   truth.

Everything runs against a synthetic mock dataset generated by this project
itself (`generate_mock_data.py`) - runnable and testable fully offline.

## Main features

- **4 fraud typology detectors**, each with a named, scored rulebook.
- **Case bundling** into a case, with `case_id` as the correlation key
  through every downstream artifact.
- **Case-scoped Network Evidence Layer**: one `generate_network_evidence(store, case)`
  call per case, returning evidence for exactly that case - never a shared,
  multi-case blob. Smurfing/reverse-smurfing get a NetworkX graph
  (Cytoscape.js-ready JSON); money mule gets a transaction timeline; account
  swap gets a **behavioral transaction-vs-time timeline** with a computed
  baseline-vs-recent deviation summary (amount/frequency ratios) - none of
  the latter two are graphs.
- **One integrated orchestrator** (`run_pipeline.py`) that runs
  DataStore → Detection → Case Bundling → per-case Evidence in a single
  process and persists real output - no manual multi-step CLI dance, no
  hardcoded/demo cases anywhere in the run path.
- **Two-sided LLM hypothesis agents** (Google Gemini) + a Contradiction
  Agent, generalized across all 4 typologies.
- **Evaluation pipeline** (`eval_pipeline.py`) scoring the LLM pipeline
  against the mock dataset's **ground truth** (a completely separate data
  source from the live pipeline's own output - see PROJECT_STATE.md).
- **Standalone graph/timeline visualization** (`visualize_network.py`) via
  matplotlib/NetworkX, no frontend required.

## Tech stack

- **Python 3**, plain functions/CLI scripts - `main.py` is a bare FastAPI
  stub (`/` health check only); no real API surface exists yet.
- **NetworkX** - graph construction/traversal for smurfing/reverse-smurfing.
- **matplotlib** - `visualize_network.py` only.
- **Faker** - mock data generator only.
- **google-genai** (Gemini, model `gemini-3.6-flash`) - the 3 LLM agents.
- **CSV + JSON** as the data layer - no database.

## How to install / run it

```bash
pip install -r backend/requirements.txt

cd backend

# 1. Generate the mock dataset (bank source-of-truth data + ground truth for eval)
python3 generate_mock_data.py --outdir mock_data --num_accounts 220 --num_cases 38

# 2. Run the COMPLETE live pipeline in one pass:
#    DataStore -> Detection -> suspected alerts -> Case Bundling -> cases
#    -> per-case Network/Timeline Evidence -> Evidence Store records
python3 run_pipeline.py --demo_case
# -> pipeline_output/suspected_alerts.csv, cases.csv, evidence/{case_id}.json

# 3. (optional) Draw a few graphs/timelines with matplotlib
python3 visualize_network.py
# -> mock_data/graphs/*.png

# 4. Run the LLM hypothesis/contradiction pipeline against GROUND TRUTH
#    (a separate, evaluation-only data source - see PROJECT_STATE.md)
export GEMINI_API_KEY=your_key_here
python3 eval_pipeline.py --limit 10   # smoke test first - costs real API calls
```

**Do not** run `detection_layer.py` and `network_layer.py` as two separate
manual steps expecting them to compose - `run_pipeline.py` is the one
integration point. (Both files still have their own `__main__` for
standalone testing of just that layer, but neither one alone produces a
complete, case-linked output set.)

## Important commands

| Command | What it does |
|---|---|
| `python3 generate_mock_data.py` | (Re)generates bank source data + ground truth (deterministic, `seed=42`). |
| `python3 run_pipeline.py` | **The** end-to-end run: Detection → Case Bundling → per-case Evidence, all in one process. Use `--demo_case` to print one full account→alert→case→evidence chain. |
| `python3 detection_layer.py` | Detection + Case Bundling only, standalone (writes `pipeline_output/suspected_alerts.csv`/`cases.csv`). For layer-level testing, not the canonical entry point. |
| `python3 network_layer.py --cases_file pipeline_output/cases.json` | Network/timeline evidence only, standalone, reading a cases file already produced by `detection_layer.py`. Also not the canonical entry point. |
| `python3 visualize_network.py` | Draws sample graphs/timelines to PNG with matplotlib. |
| `python3 eval_pipeline.py --limit N` | Smoke-tests the LLM pipeline against **ground truth**. Costs real Gemini API calls. |

## Basic project structure

```
backend/
├── generate_mock_data.py       # synthetic dataset + ground-truth generator
├── run_pipeline.py             # *** the end-to-end orchestrator ***
├── data_store.py                # shared CSV loader + in-memory indices
├── detection_layer.py           # rule-based Detection Agent + Case Intake
├── network_layer.py             # case-scoped graph/timeline Evidence Layer
├── visualize_network.py         # matplotlib graph/timeline demo
├── eval_pipeline.py             # LLM pipeline vs. ground truth
├── main.py                      # bare FastAPI stub (no real routes yet)
├── agents/
│   ├── evidence_builder.py            # assembles LLM evidence from live DataStore
│   ├── scammer_hypothesis_agent.py    # Path A: argues fraud
│   ├── legitimate_hypothesis_agent.py # Path B: argues legitimate
│   └── contradiction_agent.py         # resolves A vs B
├── mock_data/                   # INPUT: bank data + ground truth (regenerable)
│   ├── accounts.csv / transactions.csv / devices.csv / geo_events.csv / beneficiaries.csv
│   ├── ground_truth_cases.csv / ground_truth_alerts.csv / ground_truth_case_escalations.csv
│   └── graphs/                  # visualize_network.py PNG output
└── pipeline_output/              # OUTPUT: the live pipeline's own artifacts
    ├── suspected_alerts.csv / .json
    ├── cases.csv / .json
    └── evidence/{case_id}.json  # one file per case - never batched
```

**`mock_data/ground_truth_*.csv` vs `pipeline_output/*.csv` are never the
same thing and must never be confused** - see PROJECT_STATE.md for exactly
why this distinction exists and what broke before it did.

## What the user ultimately wants

Full target architecture:

```
Bank/DataStore → Detection Layer → Suspected Alerts → Case Bundling/Intake
    → Case-specific Investigation → Case-specific Network/Timeline Evidence
    → Evidence Store → Investigation/Audit Result → Human-in-the-loop Action
    → Monitor/Block/Escalate/Other final action
```

**Built and verified so far:** Detection Layer, Case Intake/bundling
(with `case_id` as the correlation key end to end), case-scoped Network
Evidence Layer (all 4 typologies dispatching to the correct visualization
type), a single integrated orchestrator, Hypothesis Agents (A/B),
Contradiction Agent, and an evaluation harness against ground truth.

**Not built yet:** a persisted Evidence Store beyond flat per-case JSON
files, Regulatory Rule Engine, Regulatory RAG, Investigation Auditor (real
completeness scoring, the completeness-score routing gate, and the
"request more evidence / re-gather" loop back to evidence gathering),
Next-Best-Action, Audit Trail, Human-in-the-loop action/escalation UI,
Case Memory, any real API layer (`main.py` is a health-check stub), a
frontend, investigator authentication, and Access Control Tiers
(role-based evidence visibility). The 3 LLM agents that exist
(`agents/scammer_hypothesis_agent.py`, `legitimate_hypothesis_agent.py`,
`contradiction_agent.py`) are called as plain sequential Python functions,
**not** as a LangGraph `StateGraph` - `langgraph` is declared in
`requirements.txt` but not actually used anywhere in the codebase yet.

See `PROJECT_STATE.md`'s "Progress against the fuller reference diagram"
section for the full breakdown against every box in the project's
architecture diagram (Intake & Detection / LangGraph Multi-Agent State /
Decision, Audit & Human Review).

See `HANDOFF.md` for exactly what's in progress right now, and
`PROJECT_STATE.md` for architectural decisions, what was broken, and why
things are built the way they are.
